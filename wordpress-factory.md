# WordPress factory

AI can complete most repeatable site production when it works inside a controlled system.

## Build flow

```mermaid
flowchart LR
    A[Successfully registered domain] --> B[Structured site brief]
    B --> C[Keyword and entity map]
    C --> D[Page and internal-link plan]
    D --> E[Copy and schema]
    E --> F[WP-CLI provision]
    F --> G[Pattern assembly]
    G --> H[Staging QA]
    H --> I[Human approval]
    I --> J[Publish]
```

## Make WordPress deterministic

- use one lightweight block theme
- create approved patterns for hero, proof, services, process, service areas, FAQ, and conversion blocks
- store phone, offer, service area, tracking IDs, and schema fields as structured data
- provision with WP-CLI
- create and update content with the REST API
- allow AI to fill approved fields and patterns
- use several controlled visual variants
- never let each build invent a new layout system

## AI ownership

- site brief
- keyword and entity map
- page outlines
- first-draft copy
- FAQ draft
- schema draft
- metadata
- internal-link plan
- image briefs
- WordPress page creation
- plugin settings from approved templates

## Human verification

- factual and legal claims
- local accuracy
- real reviews and projects
- licensing
- call routing
- form delivery
- mobile conversion
- visual polish
- final launch approval

One strong WordPress production operator should supervise the factory and handle exceptions.
